## 0. 架构速览

```
AI 宿主 ──stdio──► server（MCP 服务器）
                        │ NamedPipe \\.\pipe\bridge
Hacknet 游戏进程 ── bridge（全局插件）
                        ├─ L1 游戏通用能力（网络/文件/命令/Flag/端口/提权）
                        ├─ L2 Pathfinder 注册表泛化（run_action / registry）
                        └─ L3 modtool（[McpTool] 适配器）
                                ▲ HnpfMcpConnector（扩展插件，KE 零改动）→ 7 个 ke.* 工具
```

三层抽象：L1 覆盖游戏本体，L2 自动覆盖模组注册的 Action/Exe/Daemon，L3 暴露模组独有内存态。

## 1. 快速上手

1. `HnpfMcpBridge.dll` → 游戏 `BepInEx/plugins/`（全局）
2. `HnpfMcpConnector.dll` → `BepInEx/plugins/`（全局）或 KE 扩展 `Plugins/`（通用连接器，反射软依赖，任意扩展可用；可选，仅需要 L3 时）
3. 启动游戏 → 进 KE 扩展
4. MCP 宿主配置（选一个宿主，见 §1.1）
5. 验证：`node server/test/real-all.mjs`（16 项全绿 = 环境正常）

### 1.1 MCP 宿主接入（二选一）

**WorkBuddy**：编辑 `~/.workbuddy/mcp.json`（Windows：`C:\Users\<你>\\.workbuddy\\mcp.json`），加入：

```json
{
  "mcpServers": {
    "hnpf": {
      "command": "C:\\Users\\<你>\\AppData\\Local\\Programs\\nodejs\\node.exe",
      "args": ["C:\\Users\\<你>\\source\\repos\\LDTchara\\server\\src\\index.js"]
    }
  }
}
```

保存后，在 WorkBuddy 的连接器管理页（右上角"自定义连接器"入口）打开新加的服务器并**信任**它，即可在对话中调用全部工具。

**Claude Desktop**：编辑 `claude_desktop_config.json`（`%APPDATA%\Claude\`），同样加入上面的 `mcpServers.hnpf` 块，重启 Claude Desktop。

> 注意：`command` 用 node.exe 的**绝对路径**；`args` 指向 `server/src/index.js`。两个 host 可以同时配置。游戏未启动时工具会报 `[game offline]`，启动游戏并进扩展后自动恢复。

配置（bridge，首次启动生成 `BepInEx/config/com.HnpfMcp.Bridge.cfg`）：

```ini
[Pipe]
Name = bridge        # 多开改 bridge-{pid}
Token =                       # 握手 token（留空不鉴权）
AutoToken = true              # Token 为空时自动生成随机 token（false=保持空值不鉴权，关闭自动生成）
[Safety]
ReadOnly = false              # true=拒绝所有写操作
AllowedCommands =             # 白名单（逗号分隔，空=不限制）
BlockedCommands =             # 黑名单（逗号分隔，优先于白名单）
```

## 2. 工具完整参考

> 通用约定：`ip` 参数省略 = 当前连接节点。所有工具返回 JSON 文本。

### 2.1 状态查询

| 工具 | 参数 | 返回要点 |
|---|---|---|
| `ping` | — | pong/bridge 版本 |
| `get_state` | — | 连接节点/路径/RAM/Flag/任务/管理员/终端行 |
| `get_network_map` | — | 全节点 ip/idName/name/links/ports/用户数/可见性 |
| `get_computer` | `ip?` | 用户(含密码)/端口/daemon/文件树/防火墙状态 |
| `list_files` | `ip?`, `path?`(默认/) | 递归文件树 |
| `read_file` | `ip?`, `path?`, `file` | 文件内容 |
| `get_flags` | — | Flag 列表 |
| `get_mission` | — | 任务标题/目标完成数 |
| `mission_detail` | — | 任务详情：各目标类型+完成状态 + 任务 XML 全文（含目标参数/函数） |
| `terminal_history` | `lines?`(默认15) | 最近终端输出（命令结果在这里看） |
| `get_events` | `since?`(默认0) | 增量事件流，返回 nextId 供下次续传 |
| `registry` | — | 模组注册能力：命令/动作(**含参数**)/exe/daemon |
| `save_list` | — | 可用存档 + 项目内快照列表（运行时无法读档，见 §8） |

### 2.2 文件操作

| 工具 | 参数 | 说明 |
|---|---|---|
| `write_file` | `ip?`, `path?`, `file`, `content` | 覆盖/新建 |
| `append_file` | `ip?`, `path?`, `file`, `content` | 追加/新建 |

### 2.3 命令与连接

| 工具 | 参数 | 说明 |
|---|---|---|
| `execute_command` | `cmd`, `waitMs?` | 执行任意终端命令（§3 大全），受白/黑名单约束；`waitMs>0` 时等待并连同 terminal_history 一并返回（同步输出） |

| `run_hack_script` | `script` | 执行 .hackscript（Content 相对路径，§6 语法） |
| `launch_exe` | `exeName`, `args?` | 启动 exe（§4） |

### 2.4 端口/提权

| 工具 | 参数 | 说明 |
|---|---|---|
| `open_port` | `ip?`, `port` | 打开**已存在**的端口（原版语义，不能凭空加端口） |
| `close_port` | `ip?`, `port` | 关闭端口 |
| `take_admin` | `ip?` | 获取管理员（需先满足端口/防火墙条件） |

### 2.5 动作与 Flag

| 工具 | 参数 | 说明 |
|---|---|---|
| `run_action` | `xml` | 泛化执行 SA 动作（§5），模组注册的 Action 自动可用 |
| `set_flag` / `clear_flag` | `name` | Flag 读写（驱动 PhaseSwift/VM 等剧本） |
| `save_game` | — | 请求存档，并自动生成时间戳快照到 `HNPF-MCP/snapshots/`（保留 20 份，优先当前扩展会话存档，不进原版存档路径） |
| `launch_game` | `ext?`, `username?`, `dryRun?` | 启动 Hacknet 游戏（**正常启动到主菜单**）；`ext` 传扩展文件夹名时**后台自动经主菜单进扩展**（menu.enter_extension，插件真正加载；`-extstart` 直进已弃用——跳主菜单导致扩展插件加载异常/退出不卸载）；`username` 进扩展新账号；`dryRun=true` 只返回命令 |
| `menu_enter_extension` | `username?`, `pass?` | **主菜单进扩展**（新账号）：模拟 PF 插件确认 → 插件真正加载后进扩展；免 UI 点击 |
| `menu_load_extension_save` | `userFile`, `username`, `ext?` | **主菜单恢复存档进扩展**：走扩展菜单读档路径（`SaveGameUserName`=存档路径）；`userFile` 取 save_list 的 path |
| `pipe_probe` | `candidates?` | 探测在线 bridge 管道（多开时各实例各有管道，逗号分隔候选）；返回每个管道在线状态 |

| 工具 | 参数 | 说明 |
|---|---|---|
| `mail_list` | `ip?` | 邮件服务器账户/邮箱夹/邮件（文件名=主题）。**ip 省略时自动定位**：`netMap.mailServer`（原版默认）→ 当前连接 |
| `mail_read` | `ip?`, `user`, `folder?`(默认inbox), `subject` | 邮件全文（发件人/正文） |

> 邮件服务器说明：原版单机模式必然有默认邮件服务器（`NetworkMap.LoadContent` → `generateGameNodes` 加载 `JMailServer.xml`，`netMap.mailServer` 引用它）；**扩展模式（IsInExtensionMode）网络完全由扩展定义，不会自动生成**——扩展没定义 MailServer 节点时 `mail_list` 会报 `no MailServer daemon`（正常现象）。

## 3. 游戏内置命令大全（execute_command）

> 语法：`execute_command { "cmd": "命令 参数" }`。命令在游戏终端后台执行，结果用 `terminal_history` 查看。
> ⚠️ HN 指令与 Unix 有**关键差异**（scp 是下载不是上传、exe 是列表不是执行、connect→probe→scan 三连、analyze→solve 防火墙流程）——完整规范见 **`HN命令速查.md`**，或拉 MCP prompt `hn-command-guide`。

| 命令 | 语法 | 说明 |
|---|---|---|
| `connect` | `connect [ip]` | 连接节点（先 scan/probe 知道 IP） |
| `dc` / `disconnect` | `disconnect` | 断开当前连接 |
| `login` | `login` | 交互式登录当前节点账户（AI 需结合 get_computer 的 users/密码） |
| `ls` | `ls` | 列当前目录 |
| `cd` | `cd [文件夹]` | 切换目录（无参不回 home） |
| `cat` | `cat [文件名]` | 读文件 |
| `scp` | `scp [文件名] [可选目标]` | ⚠️ **从远程下载到本地**（默认 /bin）——与 Unix 方向相反 |
| `upload` | `upload [本地路径]` | 本地上传到当前连接目录 |
| `rm` | `rm [文件名\|*]` | 删除文件（`*` 通配；无确认，黑名单可拦） |
| `mv` | `mv [文件] [目标]` | 移动/重命名 |
| `replace` | `replace [文件名] "目标" "替换"` | 文件内容替换 |
| `append` | `append [文件名] [数据]` | 追加一行到文件 |
| `ps` | `ps` | 进程列表 + PID |
| `kill` | `kill [PID]` | 结束进程 |
| `analyze` | `analyze` | ⚠️ 分析目标防火墙（solve 前置，得方案） |
| `solve` | `solve [方案]` | 提交防火墙方案（允许 UDP 流量） |
| `probe` | `probe` | ⚠️ 扫描连接机器的**端口 + 安防等级**（不是"漏洞"） |
| `scan` | `scan` | ⚠️ 扫描连接机器的**链接并加入地图**（不是端口） |
| `exe` | `exe` | ⚠️ **列出** /bin 可用程序（不是执行）；运行用 `porthack.exe` 等 |
| `reboot` | `reboot [-i]` | 重启目标机（`-i` 立即重启） |
| `openCDTray` / `closeCDTray` | `openCDTray` | 打开/关闭目标光驱托盘（物理攻击入口） |
| `addNote` | `addNote [文本]` | 添加笔记 |
| `clear` | `clear` | 清屏 |
| `help` | `help [页码]` | 游戏内命令帮助 |
| `shell` | `shell` | 远程 shell（代理过载/IP 陷阱） |
| `mcp` | `mcp ping/state/exec` | bridge 游戏内命令 |

> exe 直接输入文件名执行（如 `ForkBomb.exe`、`porthack.exe`）——见 §4。
> `fastHack`/`revealAll`/`sudo`/`getString`/`execute` 等为模组（Pathfinder/KE）或脚本模式命令，非原版内置——以 `registry` 实际列出的为准。

## 4. 可执行程序（launch_exe）

`launch_exe { "exeName": "...", "args": "..." }`。exeName 支持：

- **内置 exe**（游戏 bin 目录）：porthack（端口破解）、forkbomb、shell、tutorial、notes、SSHcrack、FTPBounce、SMTPoverflow、SQL_MemCorrupt、Decypher、SecurityTracer、Clock 等
- **Pathfinder 自定义 exe**（#NAME# 占位符）：如 `#CUSTOMTRIAL#`、`#PHASESWIFT#`、`#EFFECTS#`、`#WPTEST#`（bridge 自动在本机 bin 补文件）
- 完整列表：`registry` 工具的 executables 字段实时查询

## 6. HackerScript 语法（run_hack_script）

> **载体是 .txt 文件**：位于 `Content/HackerScripts/*.txt`（原版）或 `Extensions/<扩展名>/HackerScripts/*.txt`（扩展）。
> 例：原版 `ThemeHack.txt`、`TrackSequence.txt`；扩展 `ExampleHack.txt`（含行为说明）。
> `run_hack_script { "script": "HackerScripts/ThemeHack.txt" }`（相对 Content；文件不存在会报错）
> 完整文档见 `Hacknet-Extension-Tutorial-main/Content/HackerScripts.md`。

**结构**：`config`（指定目标）+ 行为语句，行分隔符 `$#%#$`。

```
config [目标ID] [源ID] 延迟秒 $#%#$
行为类型 [参数] $#%#$
```

**行为表**（部分）：

| 行为 | 参数 | 说明 |
|---|---|---|
| `connect` / `disconnect` | — | 连接/断开 |
| `delay` | 秒 | 延迟 |
| `openPort` | 端口 | 开端口 |
| `delete` | 路径, 文件名 | 删文件 |
| `setAdminPass` | 密码 | 设管理员密码 |
| `makeFile` | 目录, 文件名, 内容 | 建文件 |
| `write` / `writel` / `writel_silent` | 字符串 | 终端输出 |
| `forkbomb` / `flash` / `trackseq` / `instanttrace` | — | 攻击/追踪 |
| `openCDTray` / `closeCDTray` | — | 光驱 |
| `clearTerminal` / `hideNetMap` / `showNetMap` 等 | — | UI 控制 |

## 7. 扩展结构速览（Content/Extensions 组织）

> 参考 `Hacknet-Extension-Tutorial-main/`（推荐通读其 Content/*.md 系列）。

```
游戏根目录/
├─ Content/                    # 原版内容
├─ Extensions/                 # 扩展（每个子目录一个扩展）
│  └─ <扩展名>/
│     ├─ extensionInfo.xml     # 扩展元信息（名称/作者/启动任务）
│     ├─ Nodes/*.xml           # 节点定义（Computer）
│     ├─ Missions/*.xml        # 任务定义（ActiveMission）
│     ├─ Faction/*.xml         # 阵营
│     ├─ Themes/*.xml          # 主题
│     ├─ Actions/*.xml         # 条件动作脚本（ConditionalActions）
│     ├─ Plugins/              # 扩展专属 BepInEx 插件（KE、HnpfMcpConnector 在此）
│     └─ HackerScripts/*.txt   # 黑客脚本（若扩展含） |
└─ BepInEx/plugins/            # 全局插件（bridge 在此）
```

节点 XML 关键结构（Nodes/*.xml）：`<Computer idName ip name>` + 子元素 `users`、`ports`、`firewall`、`files`、`daemons`（含 `<MailServer/>`、`<IRCDaemon/>`、自定义 daemon）。

## 8. 场景指南

### 8.1 完整渗透链（pentest-guide prompt）
1. `get_network_map` 侦察 → `get_computer` 看目标端口/用户/防火墙
2. `connect` 跳转 → `list_files`/`read_file` 拿情报
3. 对目标**已存在**端口 `open_port` 破解 → 满足条件后 `take_admin`
4. 每步 `terminal_history` 确认、`get_events` 观察

### 8.2 任务调试（mission-debug prompt）
- `get_mission` 看进度 → `get_flags` 查驱动 Flag → `run_action` 补触发条件

### 8.3 PhaseSwift 场景控制
- 状态：`ke.phaseswift.state` / `ke.phaseswift.detail`
- 控制：`run_action <PhaseSwiftScene .../>` 等 + Flag（`PhaseSwift_*`）

### 8.4 存档说明
- **游戏运行时无法读档**（Hacknet 存档只在启动时加载）——`save_list` 只列存档；要回退需重启游戏
- `save_game` 随时可存档

## 9. 故障排查

| 现象 | 原因/解决 |
|---|---|
| 工具返回 `[game offline]` | 游戏未开 / bridge 未装 / 管道名不匹配（cfg Pipe.Name） |
| `unknown method: xxx` | bridge DLL 版本旧（无该方法）→ 用最新 DLL 重启游戏 |
| `mcp` 命令不可用 | 游戏内走 CommandExecuteEvent 拦截，Pathfinder 必须已加载 |
| 连接器工具不出现 | HnpfMcpConnector.dll 未放扩展 Plugins/ 或游戏未进扩展 |
| `Could not load ... missing dependencies` | 扩展插件不能声明依赖全局插件（见设计文档 §8 连接器模式） |
| 端口打开无效 | 只能开**已存在**端口（`get_computer` 的 ports 字段）；凭空加端口是模组行为 |
| BepInEx 日志出现 `HnpfMcpBridge 未安装` 警告 | 只装了连接器没装桥 → 把 HnpfMcpBridge.dll 放 `BepInEx/plugins/` 重启 |
| `no MailServer daemon`（daemons 显示类型名但读不到） | 程序集版本 identity 问题 → 更新 bridge（运行时类型名匹配已兼容） |
| registry 里 action 无 `description` | 模组未开 XML 文档生成（GenerateDocumentationFile）或注释缺失；不影响功能 |
| `get_state` 的 `bridgeVersion` 为 null | bridge 版本探测失败（桥旧或未连上），一般不影响使用 |
| `save_list` 找不到扩展存档 | 存档在 `{文档}\My Games\HacknetPathfinder\Accounts\{扩展名}\`，需 bridge 0.1.0+ |
